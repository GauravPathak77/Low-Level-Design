## 📐 Design Principles

The foundation of robust low-level design relies on writing decoupled and flexible code. This section covers:

* **SOLID Principles:**
  * **S**ingle Responsibility Principle (SRP)
  * **O**pen/Closed Principle (OCP)
  * **L**iskov Substitution Principle (LSP)
  * **I**nterface Segregation Principle (ISP)
  * **D**ependency Inversion Principle (DIP)
* **DRY** (Don't Repeat Yourself) & **KISS** (Keep It Simple, Stupid)
* **YAGNI** (You Aren't Gonna Need It)

## 🎨 Design Patterns

Creational, Structural, and Behavioral patterns implemented with clean code examples:

### 1. Creational Patterns
* [ ] **Singleton** – Ensuring a class has only one instance.
* [ ] **Factory Method / Abstract Factory** – Creating objects without specifying the exact class.
* [ ] **Builder** – Constructing complex objects step-by-step.
* [ ] **Prototype** – Cloning existing objects.

### 2. Structural Patterns
* [ ] **Adapter** – Allowing incompatible interfaces to work together.
* [ ] **Decorator** – Adding behavior to objects dynamically.
* [ ] **Facade** – Providing a simplified interface to a complex subsystem.
* [ ] **Proxy** – Providing a placeholder for another object to control access.

### 3. Behavioral Patterns
* [ ] **Observer** – A subscription mechanism to notify multiple objects about events.
* [ ] **Strategy** – Defining a family of algorithms and making them interchangeable.
* [ ] **State** – Allowing an object to alter its behavior when its internal state changes.
* [ ] **Command** – Encapsulating a request as an object.
